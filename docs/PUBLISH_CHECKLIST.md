# 发布清单与流程审阅

## 必须收集

1. 文档实际引用的v1.10.4完整源码（本包已收集）；如现场目录改过，应从现场再导出并比较。
2. 预览所用Docker镜像中已编译Kalibr及Python绑定、ROS、OpenCV、NumPy（本包未包含实际镜像，提供导出脚本）。记录Kalibr提交、镜像ID、平台、依赖版本。
3. 标定板YAML和固定Topic、证据策略（参考文件已收集；实物尺寸待核验）。
4. README、依赖检查、启动与停止方式、报告打包、故障边界、发布验证记录（已加入）。
5. 相机桥接服务和驱动属于头环固件前置条件；如要让空白头环也能运行，需要另收集实际服务文件、程序及安装资料，当前没有。
6. IMU工具allan_variance_ros不属于四路预览必需依赖；如发布三项全流程则另需其源码/配置/构建环境及动态BAG要求，当前不宣称完整三项部署。

## 从上到下的流程问题

- 首次初始化会enable/restart SSH与相机服务，并写SD卡测试文件：应作为人工一次性部署操作，不混入只读检查或自动预览。
- IP与known_hosts处理必须核对实际设备和指纹，不能只凭一个设备在线就自动接受。
- 预览入口v1.10.4原README仍标题v1.10.3并引用多个旧路径；已保留为README.upstream.md，新增根README说明实际入口。
- 复制步骤创建设备目录，却传到live_bags；迁移时必须显式约定后续源路径。live_bags需要先建立。
- DS步骤把结果写到model_eval_ds_camera_20261012独立目录；第三步却从设备camera目录找camchain。需显式传第一步真实camchain路径或人工确认后归档，不能认为自动衔接。
- 第九步标题推荐DS，但段末说明固定P-E：文档存在两种模型规则。模型应显式选择，不能用DS测试成绩自动替换正式规则。
- P-E脚本mv可覆盖目标BAG，同目录重跑也可能覆盖结果；发布前需隔离副本并禁止覆盖。当前保留原文，未将它包装为安全通用脚本。
- DS脚本未在运行前核对BAG索引、四路类型/计数和实际解码；应加前置检查，不自动reindex原件。
- KALIBR_MANUAL_FOCAL_LENGTH_INIT的具体支持以实际容器代码为准；556不能硬编码为所有硬件型号初值。
- 第三步要求DS camchain、imu.yaml、动态相机IMU BAG；--cams依据实际help，5Hz与Camera的10Hz分开。
- 输出齐全与exit0仅表示完成；四路误差及参数合理性需另审。
- 原离线扫描20Hz、/home/key和历史磁盘路径不通用；参数化迁移前不能声称下载即可全流程运行。

原始BAG/active/orig、采集视频、设备标定参数结果、报告运行目录、SSH私钥/known_hosts/密码、ROS日志、缓存、venv、Docker镜像大包。
